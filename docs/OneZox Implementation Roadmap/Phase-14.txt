PHASE-14 — MULTI-REGION, DR, CHAOS, LEARNED ROUTER, LAUNCH   [MILESTONE M9]
================================================================================
Implements Architecture Part N.1-N.4 (multi-cell -> multi-region active-active,
HA, DR), Part N.3 (graceful degradation ladder), Part G.3 (learned router),
Part F.6 (semantic response cache), Part K (SDKs/playground), Part O (final
security hardening). Build stage 9 + 10. FINAL PRODUCTION LAUNCH.

--------------------------------------------------------------------------------
GOAL
--------------------------------------------------------------------------------
Take OneZox to production scale and launch: expand from one cell to many, then to
multi-region active-active with anycast routing and cross-region replication;
drill DR and chaos against the degradation ladder; enable the learned router and
semantic response cache behind the eval gate; package for on-prem/enterprise; and
ship SDKs, docs, and a playground. This is the enterprise-scale endgame.

--------------------------------------------------------------------------------
FEATURES IMPLEMENTED
--------------------------------------------------------------------------------
- Multi-cell scale-out within a region (scale OUT by cells, not up by fleets).
- Multi-region active-active: anycast routes to nearest healthy region; full
  region loss sheds to others.
- Cross-region replication + data-residency pinning for all stateful stores.
- Graceful degradation ladder (Part N.3): provider down -> fallback provider ->
  cheaper model -> cached/semantic response -> clear error (never a hard 500 if a
  lower rung can serve).
- DR drills + chaos game-days: kill a provider, kill a cell, kill a region;
  verify failover + degradation + RTO/RPO.
- Learned router (Part G.3): the optimizer's policy (Phase-12) routes for
  quality-per-dollar, enabled behind the eval gate.
- Semantic response cache (Part F.6): near-duplicate requests skip execution
  (with freshness policy), enabled behind the eval gate.
- On-prem/enterprise packaging (MinIO + self-host parity).
- Public SDKs, API docs, and playground.

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
INTERNAL COMMUNICATION FLOW
--------------------------------------------------------------------------------
Client -> anycast -> nearest healthy REGION -> cell router -> edge -> engine.
Region loss -> anycast sheds to another region (active-active).
Degradation ladder: provider down -> Provider Gateway signals -> scheduler
  falls back provider -> cheaper model -> semantic/cached response -> clear error.
Learned router: scheduler consults optimizer_policy (behind flag, eval-gated) to
  pick quality-per-dollar routing.
Semantic cache: near-duplicate request -> SemanticCacheLookup hit -> skip
  execution (respecting freshness) -> respond.
DR/chaos: game-day kills provider/cell/region -> verify failover + RTO/RPO.

--------------------------------------------------------------------------------
DEPENDENCIES
--------------------------------------------------------------------------------
- Upstream: ALL prior phases (00-13). Multi-region composes every service;
  learned router needs Phase-12 optimizer; semantic cache needs Phase-10 cache
  tiers + Phase-12 eval gate; DR needs Phase-13 observability.

--------------------------------------------------------------------------------
SECURITY IMPLEMENTATION
--------------------------------------------------------------------------------
- Data-residency pinning: a tenant's data stays in its home region where required
  (Part I geo-partitioning; Chat/Memory honor residency).
- Cross-region replication encrypted in transit + at rest (per-tenant keys).
- Final zero-trust review: mTLS everywhere, least-privilege, signed images +
  admission control enforced (Part O) — report-only modes flipped to enforcing.
- DR runbooks + automated failover; security sign-off in the readiness review.
- Learned router + semantic cache gated by eval (no quality/safety regression
  ships).
